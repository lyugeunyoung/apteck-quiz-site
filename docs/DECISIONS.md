# DECISIONS — 의사결정 기록 (ADR)

`PROMPT.md` §7의 "반드시 사용자에게 물어볼 것" 5개 항목에 대한 답과 근거. 새 컴퓨터에서 이어받을 때
"왜 이렇게 만들었는지"를 다시 묻지 않도록 여기에 고정한다. 결정은 언제든 재논의 가능하며, 바뀌면 이
파일에 새 항목으로 추가하고 이전 항목은 취소선으로 남긴다(삭제하지 않음).

## 1. 커스텀 도메인

**결정 (2026-09-10)**: 지금은 `*.github.io`를 그대로 사용한다. 도메인 구매는 보류.

- 근거: 유료 지출이 필요한 결정이라 사용자가 직접 판단. 매출이 증명되면 그때 재검토하기로 함.
- 영향: 네이버 서치어드바이저·독립 사이트 신뢰도 측면에서 `github.io` 서브패스의 불리함은 그대로
  감수한다. Phase 5의 나머지 항목(서치어드바이저 절차, OG 완전성, RSS 우선 제출, thin content 방어 등)으로
  최대한 상쇄한다.
- 재검토 조건: 실 트래픽·매출 데이터가 쌓이면.

## 2. 정답의 메타태그/JSON-LD 노출 여부

**결정 (2026-09-10)**: **비노출**. `description`·JSON-LD `FAQPage.acceptedAnswer` 등 메타 영역에는 정답을
직접 노출하지 않고, 본문(페이지 실제 텍스트)에만 정답을 둔다.

- 근거: 검색 결과에서 바로 정답이 소비되어 클릭 없이 이탈하는 것을 막고, 광고 노출(뷰어빌리티)로
  이어지는 클릭을 우선한다 — 애드센스 수익이 이 프로젝트의 목적이므로 트래픽 총량보다 클릭당 수익을
  택함.
- `PROMPT.md` 3.4는 초기값을 `true`(노출)로 권고했으나, 사용자가 명시적으로 `false`를 선택해 **권고안을
  기각하고 사용자 결정을 따름**.
- 구현: `data/quizzes.json`의 `site.exposeAnswerInMeta`를 `false`로 둔다(플래그 자체는 계속 유지해
  나중에 GSC 데이터로 재판단 가능하게 함).
- 재검토 조건: 4주 후 Search Console 클릭률·노출 데이터로 재판단(원안 그대로 유지).

## 3. 티스토리(bookshelf-journey)와 신규 사이트의 역할 분리

**결정 (2026-09-10)**: **보류**. 지금은 신규 사이트 완성에만 집중하고, 티스토리 쪽 콘텐츠 전략(요약+링크로
전환 등)은 손대지 않는다.

- 근거: 사용자가 아직 판단을 내릴 단계가 아니라고 봄. 두 채널을 동시에 재설계하면 범위가 지나치게
  커진다.
- 영향: 당분간 두 사이트의 콘텐츠가 중복될 수 있는 리스크(자기잠식)는 그대로 남는다. Phase 5의 다른
  항목(고정 서술 콘텐츠 확충, 아카이브, FAQ 등)으로 신규 사이트만의 차별화된 분량을 최대한 확보해
  중복 판정 리스크를 낮춘다.
- 재검토 조건: 신규 사이트가 어느 정도 안정화된 뒤 별도로 다시 논의.

## 4. 문제 이미지 소스

**결정 (2026-09-10)**: 앱 스크린샷(구글드라이브 링크)을 계속 사용한다. 자체 제작 그래픽으로 전환하지 않음.

- 근거: 사용자가 현재 방식 유지를 선택.
- 영향: `PROMPT.md` 3.6이 지적한 저작권 리스크(앱 화면 무단 게시)는 사용자가 인지하고 감수하기로 함.
  완화책으로 기존에 있던 출처·면책 문구(`disclaimer`, 각 앱 참여 방법 섹션의 "정보 제공 목적" 고지)는
  유지·강화하고, 문제 설명은 이미지 그대로 옮기지 않고 직접 요약·재작성하는 기존 원칙(§9 AS-IS 참고)을
  계속 지킨다.
- Phase 2(이미지 자산화: 드라이브 → WebP 다운로드 후 저장소 커밋)는 이 결정과 무관하게 그대로 진행한다
  — "스크린샷을 쓴다"는 선택과 "스크린샷을 어디서 서빙하느냐"는 별개 문제이기 때문.

## 5. 애드센스 자동광고 사용 여부

**결정 (2026-09-10)**: **자동광고 사용 안 함**. `PROMPT.md` 3.6에 명시된 수동 슬롯 4개(상단 display /
중단 display / in-article / 하단 autorelaxed)만 사용하고, 배치·스타일을 사이트 디자인(네오뱅크 블루
토큰, 카드 레이아웃, 여백 체계)에 맞춰 직접 튜닝한다.

- 근거: 사용자가 "광고를 웹사이트 특성과 디자인에 맞도록 새롭게 설정"을 요청 — 이는 Google 알고리즘이
  임의로 광고를 삽입하는 자동광고보다, 위치·스타일을 직접 통제하는 수동 슬롯 방식과 부합한다.
- 영향: 자동광고 대비 광고 단가/노출 기회는 다소 줄 수 있으나, 오클릭 유도·레이아웃 밀림(CLS) 리스크와
  "정답 확인 버튼 근처 광고" 같은 정책 위반 리스크를 원천 차단할 수 있다.
- 재검토 조건: 수동 슬롯 운영 데이터가 쌓인 뒤, 필요하면 제한적으로(예: 특정 위치만) 자동광고 병행을
  다시 검토.
